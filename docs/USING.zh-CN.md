# Keel 使用与支持

[English](USING.md) · **简体中文**

## 何时使用

Keel 适用于运行时共享的传输中立值、规范字节、schema 与结构化错误。大多数产品开发者应从 Rivet 或 Glaze 入手，而不是围绕 Keel 再组装一个应用框架。

## 要求与成熟度

需要 Racket 9.0+，实现仅依赖 base。本库不含 GUI、网络服务、程序安装器或商业账号。使用方在 Keel 之外维护传输信封与平台行为。

## 一次有效验证

先对小值编码再解码，在实际输入边界验证拒绝行为，并为独立实现运行共用 golden corpus。不要把编解码器手抄进产品。包 SemVer 与线协议版本各有独立归属。

## 升级、数据与支持

固定并记录应用实际测试的包版本和平台。升级前阅读 CHANGELOG 与兼容契约，在副本上测试用户数据迁移，并保留可恢复版本。框架或库不替产品提供数据库备份、发布证书、退款、账号恢复或隐私政策。不要把示例夹具中的客户、商品和金额当成真实 offer。

在 [Issues](https://github.com/turinglambdaai/keel/issues) 反馈，中文或英文均可。包含包版本/提交、Racket 版本、系统架构、最小复现和已脱敏的首条错误。不要附带真实密钥、客户凭据、支付原始数据或私密文档。社区支持不承诺响应时限。
